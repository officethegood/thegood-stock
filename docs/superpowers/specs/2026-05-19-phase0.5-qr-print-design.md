# Phase 0.5 — QR Print (cross-cutting) Design

**Status:** APPROVED — ready for impl
**Date:** 2026-05-19
**Scope:** Add QR code printing to existing scan-target entities (cross-cutting; not its own deploy phase but versioned as Phase 0.5 because it touches Phase 0 + 1 + 4 + 5 surfaces).

## 1. Purpose

ทุก phase 1/2/3/4/5/6 มีการ scan QR/barcode แต่ไม่มี phase ไหน generate/print QR เลย → ผู้ใช้ต้องไปใช้ external QR generator แล้วพิมพ์เอง = เสี่ยง typo + flow แตก. Phase 0.5 ปิดช่องนี้ด้วย shared component + dedicated Staff-accessible print page.

## 2. Scope — 4 entity types

| Entity | Source | QR payload |
|---|---|---|
| **stock_items** | Phase 1 | `sku` (e.g. `SUP-GAUZE-001`) — barcode field ถ้ามีจะ render เพิ่ม |
| **locations** (room/cabinet/shelf/ambulance) | Phase 0 | `code` (e.g. `ROOM-A`, `CAB-A-1`, `AMB-TG1`) |
| **locations type='bag'** (ALS bags) | Phase 4 | `code` (e.g. `BAG-ALS-001`) — same path as locations |
| **oxygen_tanks** | Phase 5 | `serial` (e.g. `OXY-001`) |

**ไม่ทำใน Phase 0.5:** lots, loans, movements, individual linens (no physical artifact or supplier prints lot labels)

## 3. QR payload format

**Decision: Bare code** (per PM Q-QR-1 2026-05-19)

QR string = bare entity code: `SUP-GAUZE-001` / `ROOM-A` / `BAG-ALS-001` / `OXY-001`

Rationale: html5-qrcode scanner reads bare text → existing `searchByBarcode .ilike` matches without modification. External apps (phone camera/Line/Google Lens) show text + copy — user opens our app manually. Trade-off accepted: no deep-link convenience, but zero scanner.js changes.

**ไม่ใช้ URL format** (`https://.../staff-scan.html?code=...`) — เพราะ scanner ปัจจุบันไม่ได้ extract `?code=` param + QR ใหญ่ขึ้นโดยไม่จำเป็น

## 4. Print modes

### 4.1 A4 grid bulk (default)
- Layout: 6 cols × 8 rows = **48 stickers/page**
- Sticker size: 32mm × 32mm (matches A4 label-paper standard, e.g. AAS A4-48 = 0.21 บาท/ดวง)
- Cell content:
  ```
  ┌──────────────────┐
  │   QR (26×26mm)   │
  │                  │
  │ SUP-GAUZE-001    │ ← code, 7pt Roboto Mono
  │ ผ้าก๊อซ          │ ← name, 6pt Sarabun, truncate 24 chars
  └──────────────────┘
  ```
- Multi-select checkboxes on print page → "พิมพ์ที่เลือก (N)" CTA

### 4.2 Single sticker (toggle)
- Sizes: **38mm / 50mm / 76mm** (common Brother QL / Phomemo M02 label sizes)
- One page per sticker, paper size matches
- QR auto-scales to fit minus 4mm margin
- Same content as A4 grid cell but bigger fonts

### 4.3 Print mechanism
- `window.print()` with `@media print` CSS
- A4 grid: `@page { size: A4; margin: 0 }` + flex grid
- Single: `@page { size: <Nmm Nmm>; margin: 0 }`
- Mobile printer flow: Save as PDF → user opens in printer app (Phomemo/Brother)

## 6. API contract

```js
window.QRPrint.single(code, {
  size: '38mm' | '50mm' | '76mm',
  label: string,           // human-readable code under QR (= code by default)
  subtitle: string,        // optional Thai name under code
  entityType: 'item' | 'location' | 'bag' | 'tank'  // for analytics, not in QR payload
})

window.QRPrint.bulk(rows, {
  // rows: Array<{code, label?, subtitle?}>
  // No size option — always A4 grid 6×8
})
```

Both functions: open `window.print()` immediately after rendering. CSS handles page break (single = 1 page; bulk auto-paginates).

## 7. Access control

| Role | Pages accessible | Entities can print |
|---|---|---|
| **Admin** | All admin tabs + staff-print.html | items, locations, bags, tanks |
| **Employee** | staff.html + staff-print.html + staff-scan.html + staff-oxygen.html | items, locations, bags, tanks (read-only data; print fully allowed) |

Implementation: `staff-print.html` uses `requireRole(['Admin','Employee'])` from shared/auth.js (already in Phase 0). Data fetched via REST → existing RLS allows SELECT on all 4 tables for authenticated.

**Hide sensitive fields in Employee view:** Employee sees code + name only. NOT qty, threshold, reorder_threshold, supplier, recalled_reason, current_pressure_psi. Admin can see all (but print sticker shows same minimal content for both — for sticker purpose).
