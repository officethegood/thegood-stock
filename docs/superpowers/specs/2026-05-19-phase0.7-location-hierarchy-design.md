# Phase 0.7 — Location Hierarchy Refactor + Transfer Audit

**Date:** 2026-05-19
**Owner:** PM (Pex)
**Status:** Design approved → ready for implementation plan
**Depends on:** Phase 0 (locations table), Phase 1 (stock_movements, stock_item_locations)
**Blocks / unblocks:** Sub-projects B (multi-loc display), D (linen state), E (ALS bag dual-role)

---

## 1. Background

Phase 0 ใช้ enum `location_type = {room, cabinet, shelf, ambulance, bag}` ซึ่งพอใช้ตอนเริ่มต้น แต่หลังใช้งานจริงพบปัญหา 4 ข้อจาก user feedback:

1. **Cabinet vs Rack ไม่ได้แยกชัด** — physical world มีทั้งตู้ปิด ตู้เปิด ตะแกรง ลิ้นชัก ทุกอันทำงานเหมือนกัน (container ใน room) แต่ user คิดเป็น Cabinet / Rack คนละก้อน
2. **Rack ย้าย parent ไป room โดยตรงไม่ได้** — UI rule บังคับให้อยู่ใน cabinet หมวด ซึ่งไม่ตรงกับ physical reality
3. **ตะกร้า/bin ใน shelf ไม่มีใน schema** — staff หาของในตู้ลำบาก เพราะระบบบอกแค่ "ชั้น 3" แต่จริงๆ ชั้น 3 มีตะกร้า 6 ใบ
4. **ALS Bag** ต้อง track zone ภายใน (airway/circulation/...) แต่ schema เดิม bag เป็น leaf — ไม่มี zone level

อีกหนึ่ง gap สำคัญ: **ระบบย้ายของระหว่าง location** (Transfer) ยังไม่มี FE/RPC ทั้งที่ enum `transfer_in`/`transfer_out` reserved ไว้ใน Phase 1 แล้ว — ทำให้ audit "ของหายจากไหน ไปไหน" ทำไม่ได้

## 2. Goals (อะไรที่ต้องได้)

- G1: Hierarchy รองรับ 5 ระดับ (ห้อง → ตู้ → ชั้น → ตะกร้า → item) แบบ optional ทุกระดับ
- G2: รถพยาบาล → ตู้ยา (ไม่ต้องผ่านห้อง) ทำได้
- G3: ALS Bag → Zone (CRUD เพิ่ม-ลบ-เปลี่ยนชื่อได้ตลอด)
- G4: Stock count แสดง breakdown ตามตำแหน่งจริง รวมถึง bin
- G5: Transfer system: scan QR ทั้ง source + destination — ถ้าไม่สแกนต้องเลือก manual ถึง leaf level
- G6: Audit trail: ทุก movement (transfer/issue/receive) บันทึก scanned flag เพื่อแยก human-error risk

## 3. Non-goals (deferred)

- **ไม่** ทำหน้า "stock breakdown per location" UI (→ Sub-project B)
- **ไม่** ทำ SKU edit (→ Sub-project C)
- **ไม่** ทำ linen state machine (→ Sub-project D)
- **ไม่** ทำ ALS Bag เป็น stock_item (dual role) (→ Sub-project E) — Phase 0.7 ทำแค่ zone CRUD เท่านั้น

### 4.3 Parent rules — enforced via CHECK constraint

```sql
-- Migration: 20260519070200_location_parent_rules.sql
ALTER TABLE locations
  ADD CONSTRAINT chk_location_parent_rules CHECK (
    (type = 'room'      AND parent_id IS NULL) OR
    (type = 'storage'   AND parent_id IS NOT NULL) OR  -- parent must be room or ambulance (enforced by trigger below)
    (type = 'cabinet'   AND parent_id IS NOT NULL) OR  -- legacy alias
    (type = 'shelf'     AND parent_id IS NOT NULL) OR
    (type = 'bin'       AND parent_id IS NOT NULL) OR
    (type = 'ambulance' AND parent_id IS NULL) OR
    (type = 'bag'       AND TRUE) OR  -- bag parent OPTIONAL (อาจอยู่ในห้อง หรือลอย)
    (type = 'zone'      AND parent_id IS NOT NULL)
  );

-- Parent-type matrix (เกินกว่าที่ CHECK ทำได้ — ใช้ trigger)
CREATE OR REPLACE FUNCTION validate_location_parent_type()
RETURNS trigger
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = 'public'
AS $$
DECLARE
  parent_type location_type;
BEGIN
  IF NEW.parent_id IS NULL THEN RETURN NEW; END IF;

  SELECT type INTO parent_type FROM locations WHERE id = NEW.parent_id;

  IF (NEW.type = 'storage'  AND parent_type NOT IN ('room','ambulance')) OR
     (NEW.type = 'cabinet'  AND parent_type NOT IN ('room','ambulance')) OR
     (NEW.type = 'shelf'    AND parent_type NOT IN ('storage','cabinet')) OR
     (NEW.type = 'bin'      AND parent_type <> 'shelf') OR
     (NEW.type = 'bag'      AND parent_type NOT IN ('room','storage','cabinet')) OR
     (NEW.type = 'zone'     AND parent_type <> 'bag')
  THEN
    RAISE EXCEPTION 'ตำแหน่ง type=% ไม่สามารถอยู่ภายใต้ type=% ได้', NEW.type, parent_type;
  END IF;

  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_locations_parent_type
  BEFORE INSERT OR UPDATE OF parent_id, type ON locations
  FOR EACH ROW EXECUTE FUNCTION validate_location_parent_type();
```

### 4.4 Recursive path view

```sql
-- Migration: 20260519070300_v_location_path.sql
CREATE OR REPLACE VIEW v_location_path AS
WITH RECURSIVE chain AS (
  SELECT id, name, type, parent_id, ambulance_id, active,
         ARRAY[name]::text[] AS path_names,
         ARRAY[type::text]::text[] AS path_types,
         1 AS depth
  FROM locations
  WHERE parent_id IS NULL

  UNION ALL

  SELECT l.id, l.name, l.type, l.parent_id, l.ambulance_id, l.active,
         c.path_names || l.name,
         c.path_types || l.type::text,
         c.depth + 1
  FROM locations l
  JOIN chain c ON l.parent_id = c.id
  WHERE c.depth < 6  -- safety cap (max realistic depth = 5)
)
SELECT id, name, type, parent_id, active,
       path_names,
       path_types,
       array_to_string(path_names, ' › ') AS path_display,
       depth
FROM chain;

GRANT SELECT ON v_location_path TO authenticated;
```

FE ใช้ `path_display` เพื่อแสดง "ห้องยา › ตู้ A › ชั้น 3 › ตะกร้าฟ้า"

## 5. Transfer system

### 5.1 RPC `transfer_stock`

```sql
-- Migration: 20260519070500_rpc_transfer_stock.sql
CREATE OR REPLACE FUNCTION transfer_stock(
  p_item_id        uuid,
  p_lot_id         uuid,           -- NULL ถ้า item ไม่ track lot
  p_source_loc_id  uuid,
  p_dest_loc_id    uuid,
  p_qty            int,
  p_source_scanned boolean,
  p_dest_scanned   boolean,
  p_note           text,
  p_client_ref_id  uuid             -- idempotency key
)
RETURNS uuid                         -- คืน transfer_out.id เป็น handle
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = 'public'
AS $func$
DECLARE
  v_out_id   uuid;
  v_in_id    uuid;
  v_current  int;
BEGIN
  -- Validate
  IF p_source_loc_id = p_dest_loc_id THEN
    RAISE EXCEPTION 'ตำแหน่งต้นทางและปลายทางต้องไม่เหมือนกัน';
  END IF;

  IF p_qty <= 0 THEN
    RAISE EXCEPTION 'จำนวนที่ย้ายต้องมากกว่า 0';
  END IF;

  -- Lock + check source qty
  SELECT qty INTO v_current
  FROM stock_item_locations
  WHERE item_id = p_item_id AND location_id = p_source_loc_id
  FOR UPDATE;

  IF v_current IS NULL OR v_current < p_qty THEN
    RAISE EXCEPTION 'ของไม่พอ (มี % ต้องการ %)', COALESCE(v_current, 0), p_qty;
  END IF;

  -- Insert transfer_out (negative)
  INSERT INTO stock_movements
    (client_ref_id, item_id, location_id, movement_type, qty_delta,
     lot_id, note, scanned)
  VALUES
    (p_client_ref_id, p_item_id, p_source_loc_id, 'transfer_out', -p_qty,
     p_lot_id, p_note, p_source_scanned)
  RETURNING id INTO v_out_id;

  -- Insert transfer_in (positive), linked to out
  INSERT INTO stock_movements
    (item_id, location_id, movement_type, qty_delta,
     lot_id, note, scanned, source_movement_id)
  VALUES
    (p_item_id, p_dest_loc_id, 'transfer_in', p_qty,
     p_lot_id, p_note, p_dest_scanned, v_out_id)
  RETURNING id INTO v_in_id;

  RETURN v_out_id;
END;
$func$;

REVOKE ALL ON FUNCTION transfer_stock FROM PUBLIC;
GRANT EXECUTE ON FUNCTION transfer_stock TO authenticated;
```

**Note:** `apply_movement_to_sil()` trigger (Phase 1) จะ handle update `stock_item_locations.qty` ของทั้ง 2 rows อัตโนมัติ — RPC ไม่ต้อง upsert sil เอง

**Source / destination input:**

- **Manual mode:** เปิด tree-picker modal — cascade required จนถึง leaf
  - ห้อง → (storage children) → (shelf children) → (bin children หรือไม่)
  - หรือ ambulance → (storage children) → ...

**Validation ก่อน submit:**
- source ≠ destination
- source/destination ทั้งคู่ active
- qty > 0 และ ≤ source qty
- ถ้า item.tracks_lots=true → ต้องเลือก lot

### 5.2.1 Camera fallback — กล้องไม่ติด / permission denied / device ไม่มีกล้อง

**Detection ใน `shared/scanner.js`:**

```js
async function openScanner(opts) {
  // 1) ตรวจ MediaDevices API support
  if (!navigator.mediaDevices?.getUserMedia) {
    return _fallbackToManual('device-not-supported', opts);
  }

  try {
    // 2) ขอ permission + เปิด stream (timeout 5s)
    const stream = await Promise.race([
      navigator.mediaDevices.getUserMedia({ video: { facingMode: 'environment' } }),
      new Promise((_, rej) => setTimeout(() => rej(new Error('timeout')), 5000))
    ]);
    // ... attach to video element, start QR decode loop
  } catch (err) {
    // 3) จับ error และ map เป็น fallback reason
    const reason =
      err.name === 'NotAllowedError'    ? 'permission-denied'  :
      err.name === 'NotFoundError'      ? 'no-camera'          :
      err.name === 'NotReadableError'   ? 'camera-busy'        :
      err.message === 'timeout'         ? 'camera-timeout'     :
                                          'unknown-error';
    return _fallbackToManual(reason, opts);
  }
}

function _fallbackToManual(reason, opts) {
  const msg = {
    'device-not-supported': 'อุปกรณ์นี้ไม่รองรับกล้อง',
    'permission-denied':    'ไม่ได้รับอนุญาตใช้กล้อง — ตั้งค่าใน browser หรือเลือกตำแหน่งด้วยมือ',
    'no-camera':            'ไม่พบกล้องในอุปกรณ์นี้',
    'camera-busy':          'กล้องถูกใช้งานโดย app อื่น',
    'camera-timeout':       'กล้องไม่ตอบสนอง — ลองใหม่หรือเลือกด้วยมือ',
    'unknown-error':        'เปิดกล้องไม่สำเร็จ — กรุณาเลือกตำแหน่งด้วยมือ'
  }[reason];

  // แสดง toast + เปิด tree-picker modal ทันที (ไม่ถามซ้ำ)
  Notify.warn(msg);
  return openLocationTreePicker(opts);  // returns same shape as scan result
}
```

**UX rules:**
1. **ไม่มี dead-end:** ทุกกรณีกล้องล้มเหลว → เปิด tree-picker อัตโนมัติทันที (user ไม่ต้องกดปุ่มซ้ำ)
2. **บอก reason ชัด:** toast แจ้งว่าทำไม fallback (ช่วย debug "ทำไมต้องเลือก manual")
3. **Manual selection ยัง set `scanned=false`** — audit log จะเห็นว่า movement นี้ไม่ได้สแกน
4. **Manual entry retry-friendly:** หลังเลือก manual แล้ว ปุ่ม "📷 สแกน QR" ยังกดได้อีกถ้า user แก้ permission แล้ว
5. **ปุ่ม "เลือกจากรายการ"** อยู่ในหน้า transfer modal เสมอ คู่กับ "สแกน QR" — user มี choice ตั้งแต่ต้น ไม่ใช่หลังจาก scan ล้มเหลว

**Browser-specific quirks:**
| Browser | Quirk | Mitigation |
|---|---|---|
| iOS Safari | `getUserMedia` ต้อง HTTPS + user gesture | ปุ่ม "สแกน QR" ต้องเป็น direct click (ไม่ใช่ auto-trigger) |
| iOS Safari < 14.3 | ไม่รองรับใน in-app browser (LINE, FB) | Detect → แสดง "เปิดใน Safari" message + fallback |
| Android Chrome | ขอ permission ทุกครั้งถ้า site ไม่ persist | OK, แค่ user อนุญาต |
| Desktop ไม่มีกล้อง | NotFoundError | Fallback ปกติ |
| PWA installed | ใช้สิทธิ์ camera ของ browser parent | Tested ใน Phase 0 — works |

### 5.3 Auto-migrate on sublocation add (D10)

**Trigger:** Admin สร้าง sub-level ใหม่ (เช่น เพิ่ม shelf ใต้ตู้, เพิ่ม bin ใต้ชั้น, เพิ่ม zone ใต้ bag) ที่ parent ของมันมีของอยู่ตรงๆ (stock_item_locations.location_id = parent_id, qty > 0)

**Flow:**

```
1. Admin กรอก form "เพิ่ม shelf" → parent = ตู้ A
2. ก่อน submit FE query:
   SELECT item_id, qty FROM stock_item_locations 
   WHERE location_id = '<parent_id>' AND qty > 0;
3. ถ้าได้ row > 0 → แสดง warning modal:
   ┌──────────────────────────────────────────┐
   │ ⚠ ตู้นี้มีของอยู่ตรงๆ (3 รายการ)       │
   │                                          │
   │ • Paracetamol 500mg × 20                 │
   │ • ผ้าก๊อซ 4×4 × 50                       │
   │ • Syringe 5ml × 12                       │
   │                                          │
   │ ของทั้งหมดจะถูกย้ายไปยัง                  │
   │ ชั้นใหม่ "ชั้น 1" โดยอัตโนมัติ           │
   │                                          │
   │ ท่านสามารถจัดเรียงในระดับชั้นของตู้      │
   │ เองทีหลังได้ (ใช้ปุ่ม "ย้าย" ในรายการของ)│
   │                                          │
   │   [ยกเลิก]      [สร้างและย้ายของ]        │
   └──────────────────────────────────────────┘
4. User confirm → BE flow:
   a) INSERT shelf (BE) → ได้ shelf_id ใหม่
   b) สำหรับแต่ละ item ใน parent: 
      RPC transfer_stock(item_id, lot_id?, parent_id, shelf_id, qty, false, false, 
                         'auto-migrate when sublocation "<shelf_name>" added', uuid())
5. User cancel → ไม่สร้าง shelf, modal ปิด
```

**Implementation notes:**
- Auto-migrate logic อยู่ที่ FE (`js/locations.js`) — เรียก RPC ตามลำดับใน loop
- Audit trail: ทุก auto-move บันทึก scanned=false + note อธิบายเหตุการณ์
- ถ้า item เป็น lot-tracked: ต้องเลือก lot อัตโนมัติ (FEFO) หรือใช้ lot_id เดิมที่มีอยู่ที่ parent
- Race condition: ถ้า 2 admin เพิ่ม shelf พร้อมกัน → ตัวที่ 2 ต้อง re-query items (อาจไม่มีแล้ว) → simple retry

**Edge cases:**
- ถ้า parent มี **หลาย sublocations อยู่แล้ว** + admin เพิ่ม sublocation ใหม่ + parent ยังมีของตรงๆ → modal ถามว่าจะย้ายไป sublocation ใหม่ที่เพิ่ง create หรือ sublocation เดิม? **Decision:** ย้ายไป sublocation ใหม่เสมอ (สอดคล้องกับ user intent ที่ "ของจะไปอยู่ในชั้นแรกที่เพิ่ม")
- ถ้า user cancel ระหว่างย้ายของ (network drop กลางคัน) → บาง item ย้ายแล้ว บางตัวไม่ย้าย → ระบบไม่ rollback อัตโนมัติ admin ตรวจ inventory เห็นและย้ายต่อเอง (ไม่ destructive)
- ถ้าจำนวนของเยอะมาก (e.g., 50+ items ใน parent) → ใช้ batch transfer_stock + progress indicator

### 5.4 Manual-only mode (admin/desktop)

Admin บน desktop ไม่มีกล้อง — UI **แสดง manual picker เป็น default** โดยไม่ต้องรอ scan fail:

- Detect: `navigator.mediaDevices` undefined ตอน page load → set `_cameraAvailable = false`
- ถ้า `_cameraAvailable === false` → ปุ่ม "สแกน QR" hidden หรือ disabled + label "เลือกจากรายการ" เป็น primary action
- ปุ่ม transfer ยังทำงานได้ปกติ ด้วย scanned=false ทุกครั้ง

### 5.3 Destination cascade depth — ไม่บังคับเท่ากับ source

ไม่บังคับว่า source ระดับใด destination ต้องระดับนั้น — admin ย้ายของจาก bin → shelf ตรงๆ ได้ ย้ายจาก shelf → bin ของตู้อื่นได้ การ resolve qty ใช้ leaf location_id ตรงๆ

## 6. Data migration

Pre-conditions:
- Phase 0+1 ทำงานอยู่
- มี locations ที่ type='cabinet' (Phase 0) — ต้อง migrate เป็น 'storage'
- มี locations ที่ type='rack' (ถ้ามี — ตรวจสอบ)
- stock_movements ทั้งหมดมี scanned=false หลัง ALTER (default) — accept ว่า movement เก่าทั้งหมดถือเป็น "manual" จาก audit ตอนนี้

```sql
-- Migration: 20260519070600_migrate_cabinet_to_storage.sql
DO $migrate$
DECLARE
  v_cab_count int;
BEGIN
  SELECT count(*) INTO v_cab_count FROM locations WHERE type = 'cabinet';
  RAISE NOTICE 'Migrating % cabinet rows to storage', v_cab_count;

  -- Set storage_style='closed' as conservative default
  UPDATE locations
  SET    type          = 'storage',
         storage_style = COALESCE(storage_style, 'closed')
  WHERE  type = 'cabinet';

  RAISE NOTICE 'Migration complete';
END
$migrate$;
```

**Rollback strategy:** ถ้าต้อง revert ใช้ `UPDATE locations SET type='cabinet' WHERE type='storage' AND storage_style='closed'` (lossy แต่ใกล้ original)

### 8.1 QR print — bin + zone support

**ทำไมต้องมี QR เฉพาะ:** Transfer flow (§5) ต้องสแกน source/destination ถึง leaf level — bin (ตะกร้าฟ้า/เขียว) และ zone (airway/circulation) ต้องมี sticker ติดที่ตัวจริง staff ถึงจะสแกนเข้าได้

**Decision — tab structure คงไว้ 4 tabs (ไม่เพิ่มเป็น 6):**

| Tab ปัจจุบัน | หลัง Phase 0.7 |
|---|---|
| สินค้า | (เหมือนเดิม) stock_items |
| สถานที่ | locations WHERE type IN (room, storage, shelf, **bin**, ambulance) — เพิ่ม bin |
| ALS Bags | locations WHERE type IN (bag, **zone**) — เพิ่ม zone พร้อม parent path |
| ถังออกซิเจน | (เหมือนเดิม) oxygen_tanks |

**Display rules:**

- **Bin row** — แสดง `code` + `name` + tiny breadcrumb เช่น "BIN-A3 · ตะกร้าฟ้า · ห้องยา › ตู้ A › ชั้น 3" — staff รู้ทันทีว่าตะกร้านี้อยู่ไหน
- **Zone row** — แสดง `code` + `name` + parent bag tag เช่น "ZN-01 · airway · กระเป๋า ALS-1" — distinguish จาก bag เอง
- เรียงในรายการ: bag → zones ของ bag นั้น → bag ถัดไป (sorted by bag code, zone alpha)

**QR payload format:** ใช้ `location:<id>` (เดิมที่ Phase 0.5 ใช้อยู่) — bin + zone ใช้ `locations.id` ปกติ ไม่ต้อง schema ใหม่

**Sticker layout:**
- **Bin (50×30 mm แนะนำ)** — code ใหญ่ + breadcrumb เล็ก + QR — เพราะตะกร้าเล็ก ไม่ควรใช้ 50×50
- **Zone (50×30 mm)** — code + zone name + parent bag เป็นเงา — ใช้ขนาดเดียวกับ bag stickers
- Reuse `shared/qr-print.js` `_renderLandscape5030()` ที่มีอยู่แล้ว — แค่ pass subtitle ให้ครบ

**Code generation rule (admin CRUD):**
- Bin code prefix: `BIN-` + sequence (e.g. BIN-001, BIN-002) — admin เลือก override ได้
- Zone code prefix: `ZN-` + sequence — admin เลือก override ได้
- Auto-suggest ใน FE form, save เป็น `locations.code` ปกติ

## 11. Risks

| Risk | Mitigation |
|---|---|
| ALTER TYPE บน enum ที่กำลังใช้งานอาจล็อก table นาน | enum add value เป็น metadata change ไม่ rewrite table — safe on production |
| User confusion ระหว่าง cabinet (legacy) vs storage | FE ซ่อน enum value 'cabinet' จาก dropdown หลัง migration; แสดงเป็น storage ทั้งหมด |
| Tree-picker UX บน mobile หน้าจอเล็ก | ออกแบบเป็น full-screen modal + breadcrumb + back button |
| Trigger validate_location_parent_type อาจ block legacy data ที่ผิดกฎ | Pre-migration audit: `SELECT * FROM locations WHERE parent_id ผิดกฎ` ก่อน apply trigger |
| User stuck เมื่อกล้องไม่ติด | Auto-fallback เปิด tree-picker ทันที + toast บอก reason — ไม่ปล่อย dead-end (§5.2.1) |
| Desktop admin ไม่มีกล้องเลย ต้อง scan ทุกครั้ง | Detect camera unavailability ตอน load → ซ่อนปุ่ม scan, manual เป็น default (§5.2.2) |
| iOS in-app browser (LINE/FB) ไม่รองรับ camera | Detect → แสดงข้อความ "เปิดใน Safari สำหรับสแกน" + manual picker ทำงานปกติ |
